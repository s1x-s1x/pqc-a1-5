## Questions And Controls

The first signing metric is the complete native pid3/t12 signing function,
with the cache already loaded, one physical CPU, and independent REF self-check
inside the boundary. Account for stream/table setup, full rounds, address and
input layout, F/H work, tree work, serialization, checking and wiping. Cache
build/load, key generation and budget transactions are separate preparation
metrics; application totals must account for them without duplicate addition.

K0 uses the unchanged baseline commit. K1=F8 for A8 comparisons; K1=F1 for AF
comparisons. Match B1 and the persistent object/lifetime within each pair.
F1/AF active secret U is 272 B, but both reserve a 2304 B stream union. This
prototype also reserves all q tables. B0 in each new stream uses byte layout
and numeric loads; this is a feasible control. B1 uses direct numeric layout.
B2 is excluded. Added common FORS stack/node wiping also applies to the new
generic/F8 controls; quantify it versus unchanged K0, rather than assigning all
cleanup changes to recursion. Necessary numeric representation in F1/AF is
charged to that mode; B1 controls its concrete byte construction increment.

Compare F8/A8, F1/AF, representation F8/F1 and A8/AF, and B0/B1 as separately
registered questions. V1's main control is the current AVX2 verifier with V1
off, with identical fixtures, backend and resources. REF remains a correctness
control. No confirmation claim that A2 exceeds A1 follows from a five-config
subset lacking A8/F8. Do not add estimated percentages or work-count ratios.

## Execution And Statistics

After explicit performance authorization, first record CPU affinity, SMT/NUMA,
governor, hardware/toolchain and any quota, freeze the comparison family,
endpoint, cache policy, initialization/cleanup boundary and failure rules.
Use ordinary release libraries without counters/test hooks/global AVX2 flags.
Use identical key/message/context/randomization within a signing pair, with
atomic budget reservation before every signing attempt and no failed refund.
Validate returned signatures independently outside timing as well.

Independent key batches are statistical units; repeated calls with one key are
aggregated, not counted as independent keys. Tuning data, independent pilot and
formal data remain distinct. Pilot N and formal N are currently null, to be set
by the registered variance/resource protocol. Freeze formal N once before the
formal campaign; do not append samples based on significance. Register all
primary comparisons and multiplicity handling. Keep all raw failed/interrupted
records and predefined exclusions; being slow is not an exclusion reason.

V2 production, P99, throughput, energy and TLS/network metrics remain outside
this package. Their eventual arrival/key/invalid mix, queue limits, waiting
policy and independent run/block units require a separate workload protocol.
P's exact calls/compressions, cache bytes and selection regions are analysis,
not time. Candidate-specific full security applicability precedes new native
parameter experiments. Physical side-channel experiments have their own gate.

## Mature External Comparators

Fixed ISA-L/GmSSL/OpenSSL source versions are recorded in the neighbor manifest.
Before an external timed comparison, accept the actual adapter on the same
byte-constructed blocks and full256 outputs, bind licenses/compiler flags, and
allow equal fixed-prefix/short-block adaptation and wiping. Report general API
versus adapted costs separately. Execute only supported instructions; an
AVX-512 or SM3-NI name does not establish hardware support. External adapter
acceptance and sample-size registration are performance-phase preparation
steps, not measurements already obtained by this package.
