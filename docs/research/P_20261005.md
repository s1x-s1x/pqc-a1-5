## 1. 范围、来源与采用决定

本轮固定 `n=16,h=22,d=1,lgw=2,len=68`，分析当前 pid3 的 `a24/k6` 和三个公开近邻 `a21/k7`、`a19/k8`、`a17/k9`。缓存集合固定为 `t∈{10,12}`，得到八个参数/缓存对象。没有建立新 pid、OID、生产密钥或缓存格式，也没有改变项目现有 pid3 的交付状态。

公开来源固定为 [slh-dsa-rls commit 375c69e](https://github.com/chrisfenner/slh-dsa-rls/tree/375c69e638b079fdf4bb8ef10c9c3549f08e05f9)，本轮真实读取 README、`pkg/slhdsa/param.go` 和 Apache-2.0 许可。原字节副本、URL、SHA-256、匹配的表格行保存在 `validation/incremental-20261005/parameters/sources/` 和同目录 `manifest.json`。README 第 119/121/129/136 行分别给出 `rls128cs1/3/11/18`，当前 pid3 的结构与 cs1 对应。README 的 `w=2` 列由源码 `LgW` 注释和 `w := 1 << p.LgW` 确认是 `lg(w)=2`。

这些近邻属于公开参数继承。上游已有参数搜索、签名字节/签发/验证权重和完整上层缓存选项。本轮增加的是项目路径下有限缓存、公开表示对象、活跃 key/worker、签后自验和可解释负载边界的分析。没有声称参数或一般搜索方法原创。

上游 `VerifyHashes` 用 `len*2^lgw/2` 近似 WOTS 恢复步数，缓存成本还采用完整 hypertree 缓存。项目本表采用当前执行路径、有限 t 和精确均匀 WOTS 期望；所以不导入 README 的 `verify time`、`sign time` 或类别标签作为项目结果。这些列也不是本轮取得的时间测量。

采用决定：保留八个对象作分析候选；生产交付主参数继续为 pid3。三个新参数的原生适配和整体适用性论证后置，固定 pid3 的 A/B/V 验收独立推进。

## 2. 精确公式与计数口径

工具只调用既有 `parameter_grid.theoretical_cost`、`count_model.cache_model` 和 `security_terms.fors_probability` 的分析 API。没有加载本地 C 库、构造完整签名或执行计时。内部消息长度固定为 64 B；所有比较使用同一均匀 WOTS 消息模型。

```text
B(p) = n[1+k(a+1)+h+d*len]
C_FORS(p) = 3k*2^a+1
C_auth(t) = 274(2^t-1)-t
M_cache(p,t) = n[2^(h-t+1)-1]                 (d=1)
B_cache_file(p,t) = 96+n*2^(h-t)
```

## 3. 准备成本与生命周期

准备模式分别为：新建 key 时同时建立缓存、已有 key 重建缓存、加载已有缓存、预载完成。前两种都构建完整高度 22 的 top XMSS，t 只影响缓存存储，并不减少其叶工作；初次 keygen 自带缓存时也不再额外加一次 cache-build。

加载缓存只重建公开上层节点：t12 有 1023 H，t10 有 4095 H。校验摘要是既有七字段计数器之外的一次完整 SM3 hash，工具分别报告它的 258/1026 个压缩块及总 load 压缩数，明确区分 counted 与 uninstrumented。加载的文件 I/O、分配、元数据检查和擦除没有时间数据；逻辑调用目标不声称覆盖全部服务开销。

参数 p 在 key 创建时固定。t/e/v 的切换属于公开执行配置，缓存仍绑定 pid、公钥和 t。多副本、多设备使用同一 key 时累计签名预算仍按严格 `2^24` 解释；分析没有放宽限制。完整安全资料不足的新候选保持分析状态，数学外推也不会自动成为应用准入。

## 4. 有限资源模型与约束

生成 32 个 `(p,t,e)` 表示形状，`e∈{F8,A8,F1,AF}`。模式成本保持未知，空间项按计划对象建模：持续秘密展开 F8/A8 为 2176 B，F1/AF 为 272 B；共同项公开偏移为 2176 B；递推模式的 q 个差分记录为 `272q` B。用 `z=min(a,24)`、`q=z-3` 描述有限形状。pid3 的 q=21；新参数模式仅为假设表示形状，尚待原生适配，未把当前仅 pid3 的实现资格扩大到其他参数。

```text
worker_workspace = reserved_stream + reserved_tree_stack + auxiliary_reserve
M_total = active_keys*M_cache
        + workers*worker_workspace
        + public_table_copies*(offsets+deltas)
        + verifier_buffers + other_live_memory
```

默认示例明确给出：一个 key、一个 worker、每 worker 辅助保留 16384 B、verifier buffers 16384 B、其他存活对象保留 65536 B、同 q 的公开表共享一份。辅助保留承担工作快照、指针、轮状态、F/H scratch、编译器副本等尚未测量部分；这是对象形状加设计保留量，未声称实测峰值 RSS 或全部编译器 stack 的精确上界。异 q 的表应分组相加；异 key 的秘密表示各自计入。调用者可增加这些预算项，避免用同一份空间重复补贴两个优化。

完成内核后资源表已按实际保留容量修订：64 位构建的 stream 对象在四模式中均为 2304 B，固定树栈及 level 数组为 3300 B；公开 Delta、全部 q 的 P 和 atomic 初始化状态共保留 53676 B。已填充的秘密表示仍分别为 2176/272 B，单 q 活跃公开偏移为 2176 B，但这些活跃字节不替代实际分配容量。pid3/t12 的四模式模型总量均为 190336 B，包含上述显式辅助保留量；四 worker 时公开表只计一次，每 worker 对象容量按四份计入。候选参数采用相同容量的假设适配以供公平分析，仍保留原生适配待核身份。该模型不是实测 RSS 或完整编译器栈上界。

`constraints.csv` 输出四个明确预算例子的全部排除理由：总 RAM、缓存文件总量、签名大小、每 worker 工作区、原生参数登记。单 key/512 KiB 下八个参数/缓存对象均可分析；四 key/四 worker/512 KiB 时 t10 被 RAM 等约束排除，t12 仍可行；签名上限 3856 B 时只保留 pid3。`require_native_parameter=True` 明确排除三个未登记参数。这里的可行性是分析约束可行性，整体密码适用性另设关口。

v∈{V0,V1} 的缓冲占用由显式 verifier reserve 承担，V2 的 queue 预算须由其有界设计另行填入。不用源级原语数推定 v/e 的耗时，未取得目标工作负载与时间数据时保留 `F_x,S_x,G_x` 三组未知量。

## 5. 选择区域、Pareto 与有限后悔值

对固定可行集合 X、相同资源/生命周期、同单位 β，输出：

```text
C_x = preparations*F_x + Q*S_x + V*G_x + N*B_x*beta
x 优于 y 的区域：
preparations*(F_x-F_y)+Q*(S_x-S_y)+V*(G_x-G_y)+N*beta*(B_x-B_y) <= 0
```

工具分别生成 calls/compressions、load/build/none 的 168 条精确两两边界。calls 下 β 的单位为逻辑调用等价/字节；compressions 下为压缩等价/字节。它们是用户选定的分析权重，没有自动换算毫秒、带宽或网络能耗。若使用真实时间，则 F/S/G/β 都须由以后明确开启的实验取得，并按批量/tile/排队场景建模。

同 t 的 pid3 与 cs18，默认含 REF 自验、仅计调用，有：

```text
C_pid3-C_cs18 = 298450932*Q -12*V -192*N*beta
```

Nβ=0 时，`V/Q=24870911` 是这两者的精确边界；签发侧倾向 cs18，验证极多时 pid3 的较少验证工作可抵消。该边界只比较两个分析对象；其他候选仍参加八对象共同选择。缓存 load 模式下，t10 相对 t12 的准备额外 3072 次 H，而每次签发节省 841726 次调用，所以零签发时 t12 更省 load 工作、一次签发时 t10 更省合计调用；实际选择仍受 RAM 约束。

以签发/自验、外部验签、签名大小、cache RAM/file、load 压缩为平行目标，八个对象均在有限 Pareto 集合中：小缓存省空间/准备，高缓存省后续签发；小签名与低 FORS 签发量也互有取舍。

四个显式合成场景为签发一次、签发一次且验证/传输 `2^30` 次、签发/验证各 1024 次、零签发且验证/传输 `2^30` 次。只计算整数和有理式，没有执行这些次数的密码操作。固定单 key/512 KiB 可行集合中，场景 0/2 的签发主导条件倾向 cs18/t10，场景 1 的验证/通信主导条件倾向 pid3/t10，场景 3 的零签发条件倾向 pid3/t12。对这四场景的最大绝对后悔值选择 cs11/t12；该结果依赖场景与 β=1/64 等价权重，仅说明联合模型可解释折中，不是部署推荐或全局最优。固定 X 的最大后悔值计算采用同一候选集合，不在各场景偷偷切换可行集合。

## 6. 安全适用性与后置关口

`parameter-applicability.json` 为每个对象保存独立条目。四个参数的结构约束及 `2^24` 观察量下 FORS **目标覆盖概率项**计算完成；区间文件沿用项目的精确二项递推、定向 Decimal 舍入和正尾界。该项的 `-log2 P` 约为 128.629724、128.559978、130.395721、128.146041，只描述工具明确的单项随机目标事件。

这些数未导出整体 EUF-CMA 界、NIST 类别或量子安全位数。共同的待核事项为：完整论证与版本；签名观察数及攻击查询、多目标损失；经典/量子口径；PRF/FORS/WOTS/hypertree/消息哈希各项；SM3 替换的原语族假设；参数编码/OID、缓存/密钥身份；独立 REF 向量及预算实现。上游 README 的类别描述不自动转移给 SM3。项目历史 pid3 说明和既有验收保持其原适用范围。

新参数进入原生研究原型前需补齐上述适用性表和独立身份。当前分析结果可以用来限定未来研究集合，其工作量比和逻辑选择区域仍不承担安全准入或提速结论。
