# B1 / A1 / A2 internal kernel, 2026-10-05

This implementation binds to the fixed pid3 SM3 instance (n=16, a=24,
k=6). It preserves all 64 SM3 rounds, the full eight-word feed-forward and
the subsequent 128-bit truncation. No performance measurement was performed.
The implementation is an equivalent computation of the existing instance;
these tests do not establish overall cryptographic security or novelty.

## Files and configuration

- `c/src/sm3_incremental.h`, `c/src/sm3_incremental.c`: hidden internal API.
- `c/tests/test_incremental_kernel.c`: independent non-timing checks.
- `A15_INCREMENTAL_B1`: default 0, permitted 0/1.
- `A15_INCREMENTAL_MODE`: default 0; 1=F8, 2=A8, 3=F1, 4=AF.
- Diagnostics are emitted only with `SLH_TEST_BUILD`.
- AVX2 workers have a function-specific target attribute. No global
  `-mavx2` is used. The caller checks hardware availability; stream
  initialization returns the generic-fallback result on unsupported CPUs.

Mode 0 is the engine's existing K0 path. F8/A8 use the same persistent
eight-lane schedule and read-only round consumer. F1/AF use the same scalar
common schedule and per-round reconstruction with 68 public P vectors.
F8/F1 rebuild a complete schedule between batches; A8/AF instead apply the
public carry delta. B1 is independently selectable in all four modes.
B1=0 independently serializes bytes before loading numeric words; B1=1
constructs numeric words directly. Neither uses PRF-to-F B2 transfer.

## Integration contract

Compile `sm3_incremental.c` as a separate translation unit, together with
the existing `sm3x8.c` CPU detector. Include `sm3_incremental.h` in the
engine. Add the source/header and effective configuration to its build stamp.

For B1 in `thash8_mask`, copy the eight complete lane addresses into an
`adrs[8][32]` temporary and call
`a15_sm3i_thash8(midstate, adrs, inputs, n, 1, out)`. Use the existing path
when it returns 0. Keep the original active-mask logical counts and fault
hooks. The helper evaluates all eight defined lanes and does not count calls.

For a pid3 FORS subtree, create a local `a15_sm3i_stream` and initialize:

```c
int enabled = a15_sm3i_init(&stream, seed_h, adrs, skseed,
    start, z, pid, a, k, A15_INCREMENTAL_MODE, A15_INCREMENTAL_B1);
```

`enabled==1` indicates a real candidate stream. Result 0 requests the old
generic path (q=0 or absent AVX2); -1 denotes an invalid contract. Retain
the original backend/SM3 eligibility gate. Input seed/address/secret buffers
must not overlap the stream. Initialization copies their values and clears
any previous state. It normalizes the copied PRF type to 6 and height to 0.

Inside the unchanged leaf loop, `a15_sm3i_next(&stream, nodes)` emits the
eight PRF results in original lane order and prepares the next batch.
Manually preserve eight logical PRF/compression counts. The existing PRF
fault point follows this call; F, its leaf fault point, stack merging and
authentication capture retain their original order. Tree-address mutation
does not affect the copied stream snapshot. The selected secret's separate
PRF is left to the original code. The helper does not generate it.

`next` returns 1 for every batch including the last. It clears the stream
after the last batch. Call `a15_sm3i_clear` on all engine exits as well.
Alternatively use read-only `consume` then `advance`; the last advance
returns 0 and clears. An invalid/NULL-output `next` clears the stream.
Output buffers must not overlap the stream. Existing cancellation/error
semantics stay with the caller; this API adds no asynchronous cancellation.

## Exact layout and integer bounds

The compressed address is `adrs[3] || adrs[8:16] || adrs[19:32]`.
Payload lengths are restricted to 16/32 bytes, giving final lengths of
816/944 bits after the cached 64-byte prefix. The index occupies offsets
18..21 and hence the low 16 bits of W4 plus the high 16 bits of W5.

Stream initialization accepts only pid3/a24/k6, 3 <= z <= 24, start aligned
to 2^z, and an end within both 2^32 and the real six-tree forest. Arithmetic
for size/end uses uint64_t before narrowing. q=z-3, batches=2^q, and lane
index is start+(lane<<q)+step. q=0 returns fallback even though decomposition
is mathematically valid. No short-stream threshold was chosen using time.
Update occurs only when the next batch exists. The carry index is derived
from a strictly positive next step, so no zero ctz or overflowing shift is
used. The test-only seek reinitializes a schedule at a chosen public step;
it is absent from production and tests high carries without huge loops.

## Public tables and secret lifetime

The process has shared, key-independent carry deltas (21*68*4=5712 bytes)
and offset storage for q=0..21 (22*68*8*4=47872 bytes). Offset tables are
initialized lazily per q. Each q publication and the delta publication use
C11 atomic acquire/release state, and no caller writes a published table.
The one-time setup includes a temporary public three-basis array of 816
bytes. No secret is used during public initialization. Full reserved table
memory is charged even for untouched q values; these are not per-thread
secret costs or a claim of reduced total working set.

The stream object is 2304 bytes in the tested 64-bit build. It reserves a
2176-byte union so all controls have identical object shape. F8/A8 fill it
with secret W[68][8]. F1/AF fill only 272 bytes with secret U[68]; the unused
1904 bytes remain zero. Thus 272 is the active persistent expansion
representation, while the actual object reservation remains 2304 bytes.
The copied seed state, 32-byte address and 16-byte secret seed are separate
snapshot costs; the 16-byte seed copy is cleared with the object.

The A2 round consumer reconstructs only the two current W vectors. It does
not create a complete secret W[68][8] temporary. Its addressable round
workspace contains initial state, eight round vectors, two message vectors,
six intermediate vectors and serialization scratch; the whole workspace is
cleared on return. Full 256-bit output is a 256-byte temporary cleared after
128-bit copies. F8/A8 schedule updates are separate from this consumer.
The common F/H B1 helper separately owns and clears its input words,
2176-byte schedule and complete output; these costs are not attributed to
the U representation reduction. Caller F/H/tree stack and fault output
buffers retain their own clearing obligations.

`a15_secure_zero` checks support addressable-memory erasure. Neither source
clearing nor these tests prove register/spill coverage, physical side-channel
resistance, or a reduced peak secret footprint by a factor of eight.
New choices depend on public parameters, mode, input length, q, step and
indices. No table lookup or branch depends on secret seed bytes.

## Independent correctness coverage

The test independently constructs 64-byte blocks from SPEC bytes and uses
the existing scalar raw SM3 compressor for full 256-bit expected results.
Its scalar message expansion is separate from candidate helpers. Coverage:

- 512 GF(2) input basis vectors in every lane; all 68 W and 64 W' words.
- Independently byte-constructed public offsets for every q=0..21 and lane.
- PRF/F/H-sized layout, padding, length, arbitrary complete addresses,
  numeric lane order, full digest and 128-bit truncation.
- All four modes and both B1 values, q=1..21, q14/15 split-word lane offsets,
  every carry position, full small streams, final batch and forest end.
- UINT32_MAX layout independently checked; stream admission rejects it
  because it exceeds the real pid3 forest.
- Copied snapshots remain correct after caller seed/address mutation;
  repeated key/address/mode changes and reinitialization.
- Whole stream unchanged after consume; unused U-union bytes remain zero;
  exhausted, explicit-clear, invalid input and error-next erasure.
- 88 table-publication streams, using 32 OpenMP threads when available,
  initialized before serial table use to exercise publication races.
- q0/no-AVX fallback, invalid size/parameter/alignment/range/mode/NULL and
  stream/output alias rejection.

The basis checks support the linear expansion model. Full round tests,
integer/lifecycle checks and engine-level integration evidence are separate.
The diagnostic binary never obtains time, cycles or profiling data.

## Reproduction and current results

Correctness-only native build (GCC/Clang, no global AVX2):

```sh
gcc -std=c11 -O2 -Wall -Wextra -Werror -Wpedantic -fopenmp \
  -DSLH_TEST_BUILD -Ic/src c/tests/test_incremental_kernel.c \
  c/src/sm3_incremental.c c/src/sm3.c c/src/sm3x8.c \
  -o build/test_incremental_kernel
build/test_incremental_kernel
```

Windows GCC 16.2.0/UCRT local check passed: 5,159,276 assertions,
512 basis inputs, 4,264 stream batches, 88 publication streams.
An additional `SLH_DISABLE_AVX2` build passed the fallback/zero-state check.
Both builds used strict warnings as errors. The full record should bind the
current source hashes, compiler identity and command independently.

Linux GCC11 normal and ASan/UBSan runs in
`validation/incremental-20261005-kernel-r1` each passed 5,159,276 checks.
The final ten-configuration tree/counter matrix is in `integration-r2`; final
AF+B1 complete signing is in `full-af-r2`. The unchanged production kernel also
has full A8 and fault-5 evidence, with historical harness identities explicitly
retained in `EXECUTION_20261005.md`. Real CUDA exclusion and full verifier
request isolation are in `isolation-r2`. Build a sanitizer binary with the same sources, adding
`-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer`.
No performance sample was produced: the count remains 0.
