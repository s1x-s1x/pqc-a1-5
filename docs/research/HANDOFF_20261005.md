## 实现与配置

基线提交为 `4ad41308ad537e0578f6dea6d85ebcd7535c46b1`。最终源码身份、构建产物和证据摘要见 `validation/incremental-20261005/final/freeze.json`；原基线源码保存在 `validation/incremental-20261005/K0-source.zip`。

| 开关 | 默认 | 可选值与作用 |
|---|---:|---|
| `INCREMENTAL_MODE` | 0 | 0 原路径；1 F8 完整八路展开；2 A8 连续地址递推；3 F1 完整共同项展开；4 AF 共同项递推 |
| `INCREMENTAL_B1` | 0 | 0 独立字节构造；1 PRF/F/H 直接字级构造 |
| `INCREMENTAL_V1` | 0 | 1 启用 pid3 单请求 FORS 同层 x8 验签 |

A2 选择基于对齐 lane 分解机制，未按速度选型。F8/A8 使用相同持续工作区和只读轮函数；F1/AF 使用相同共同项、公开偏移及轮端重建，完整展开与递推可独立比较。B1 在四种模式中均可切换。无新增公共 ABI，也未加入全局 `-mavx2`。

pid3 的编码、截断、公钥绑定、64 轮及 feed-forward、认证路径、随机化、签发预算和独立 REF 签后自验保留。其他参数、REF、CUDA 的本轮候选资格受到原有分派条件限制；q=0 与未支持 AVX2 的流回到原路径。非法开关及发布版测试钩子被编译拒绝。

## 状态与资源

秘密 stream 为每子树局部对象；地址、seed midstate 和秘密 seed 由初始化复制。公开差分表与秘密 W/U 分离，使用 C11 atomic 发布，退出和错误路径执行清理。V1 的临时 lane/node/pair 为每请求局部对象，无新增生产队列或共享可变请求状态。新分支与索引依赖公开形状、模式和地址。

stream 实际保留容量为 2,304 B。AF 活跃共同项 U 为 272 B，未使用 union 空间仍保留，故不宣称总工作集缩小八倍。公开表及 atomic 状态总保留量 53,676 B；树栈模型 3,300 B。默认单 worker pid3/t12 资源形状合计 190,336 B，是分析模型，未实测峰值 RSS。编译器栈帧检查也不等于整体峰值内存测量。

P 覆盖 8 个参数/缓存配置、32 个资源形状、168 条精确选择边界，包含独立 REF 自验。t12→t10 差为 841,726 次逻辑调用，压缩数差为 893,950。新参数保留分析身份，整体安全适用性及原生编码/向量尚待独立审查。

## 复现与性能边界

原有默认 Make 目标只构建库。候选构建示例：

```sh
make -C c OUT=../build/incremental-candidate INCREMENTAL_MODE=4 INCREMENTAL_B1=1 INCREMENTAL_V1=1 all
python -B tools/run_incremental_correctness.py --phase kernel --run-dir validation/new-kernel-run
python -B tools/run_incremental_correctness.py --phase v1 --run-dir validation/new-v1-run
python -B tools/run_incremental_correctness.py --phase integration --run-dir validation/new-integration-run
python -B tools/incremental_perf_plan.py --check
python -B tools/freeze_incremental.py --check
```

原生正确性在已有 Linux AVX2 环境执行，run-dir 使用未存在目录。完整签发须先绑定已有 cache 和预算；日常复现优先使用已有验签夹具。收尾 isolation 工具直接读取公开 JSON 的 pk/sig/message/context 四个字段，可在同一环境执行 `python -B tools/close_incremental_correctness.py --output validation/new-isolation-run`。该工具不签发、不计时；实际 CUDA 验收要求原有 NVCC/GPU 环境。

GitHub 正确性 CI 增加 kernel/V1/十配置集成及分析模拟，未加入完整 pid3 签发或性能任务。所有新性能开关默认为 0，性能计划的 `performance_enabled` 与 `execution_permit` 均为 false，样本数组为空，`results.csv` 只有表头。历史性能数据按原版本保存。

后续性能协议、12 组配置和空结果模板见 `PERFORMANCE_PROTOCOL_DRAFT_20261005.md` 与 `validation/incremental-20261005/performance/`。正式 N、pilot N 和 V1 实用阈值待注册，外部 adapter 先做正确性验收。后续入口可使用：“开启性能阶段，先验收成熟对照 adapter、冻结 pilot/统计协议及采样边界，再开始计时。” 本轮到此停留在首次性能测试之前。
