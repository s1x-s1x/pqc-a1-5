发现的反例（完整推导位于 `review_artifacts/t1_proverif/results/`）：

```
1. 两把签名密钥均泄露：攻击者选择自己的 DH/KEM ClientHello，为相应 transcript
   生成两份签名，在不存在诚实 ServerFlight 的情况下触发 ClientAccept，并推导出
   application_secret。

2. 移除 PQ 验证且经典密钥泄露：同一攻击只需伪造经典签名，即可同时破坏 flight
   一致性和应用密钥机密性。

3. 基线模型中的客户端后继消息一致性：攻击者本身可以充当合法但未认证的客户端，
   与诚实服务器完成一个新会话，推导该会话的密钥并发送受保护的握手后消息。
   ServerAcceptedPost 因而可以在没有诚实 ClientPost 的情况下发生。这是协议缺少
   客户端认证的预期结果，不是重放攻击。

在无界复制下，基线及两个单密钥泄露模型中均未发现破坏服务器 flight 注入式一致性的
跨会话重放攻击。
```

关于作者特意留空的 KEM 建模选择，我采用了以下方案：

```
使用不透明的 kem_encaps(pk,r) 和 kem_shared(pk,r) 构造子，唯一的重写规则为：

kem_decaps(kem_encaps(kem_pk(sk),r),sk) = kem_shared(kem_pk(sk),r)

封装者能够知道自己生成的共享秘密，但诚实密文不会泄露 r，也不会向攻击者提供公开的
解封装预言机。这避免了 PKE/aenc 抽象中“由攻击者选择作为共享秘密的明文”这一问题。
它仍然属于完美密码学抽象，并不能替代 IND-CCA 计算证明。
```

模型局限：静态证书信任以及成功协商混合算法均被作为前提；签名原语是完美且确定性的；
模型没有表示 XMSS 状态。完整适用范围见 `review_artifacts/t1_proverif/README.md`。

## T2——计算归约

- [x] 我**首先**攻击了 `min(Adv_EUF-CMA(classical), Adv_EUF-CMA(PQ))` 界。
      结论：
      - [ ] 按原文成立
      - [x] **按原文不成立。** H0 允许攻击者腐化任意一把签名子密钥，因此针对该
        签名方案的归约无法同时嵌入挑战公钥并回答相应的腐化查询。直接反例：假设经典
        签名已完全可伪造，优势约为 1，而 PQ 签名的攻击优势为 `epsilon`；攻击者腐化
        PQ 密钥，诚实计算 PQ 签名，再伪造经典签名。协议认证攻击优势约为 1，但所声称
        的右侧仅为 `min(1, epsilon) = epsilon`。
- [ ] 已实例化安全模型，包括会话标识、伙伴函数及 freshness 谓词——**没有**。
      随包 KEMTLS 论文附录 B 中的 `Corrupt(U)` 是参与方级查询，返回参与方的长期
      私钥；它不是骨架中新引入的“只腐化复合凭据中一把子密钥”的接口。当前没有针对此
      协议的 DFGS 模型实例。
- [x] 原文所称 `M_CV` 前缀无歧义步骤本身并非必要：`M_CV` 由固定前缀和定长摘要
      构成。真正需要证明的是握手 transcript 序列化的单射性／无歧义解析，以及
      SHA-256 抗碰撞跳步。线路格式文档描述了长度分帧，但没有在安全游戏中形式化。
- [ ] `epsilon_sim` 已被定界或证明无关——**没有**。它目前隐藏了双密钥证书中的
      挑战密钥放置、自适应部分腐化、多用户／多会话猜测损失、签名预言机模拟及阶段
      记账等实质问题。
- [x] XMSS 假设已明确声明为运行条件，而不是已由密码学归约消除的假设。可执行的
      索引测试不能证明部署环境中的状态持久化和崩溃安全。

一句话结论：

- [ ] **归约完成**
- [x] **归约无法闭合**，失败位置包括：**H0/H2（部分腐化下的 `min` 界）、模型及
      freshness 实例化、精确 flight 与 EUF-CMA 的差异、H1 的鲁棒组合器论证，以及
      未定界的模拟／紧致性损失**。完整分析见
      `review_artifacts/t2_reduction_findings.md`。

认证 `min` 界失败是本任务一个明确且关键的成功发现。正确的定理必须拆分腐化分支：
经典密钥被腐化的分支由 PQ 不可伪造性约束；PQ 密钥被腐化的分支由经典不可伪造性约束；
只有无腐化分支才可能取两个优势的最小值。全局自适应定理需要求和界或按分支加权的界，
并显式给出损失，不能使用当前无条件的最小值。攻击者可选择泄露哪个密钥交换分量时，
密钥机密性的 `min` 界存在同样的问题。

另一个可执行验证出的证明缺口：实际 ECDSA 验证器会接受同一消息签名的另一种
`(r,n-s)` 编码，见 `review_artifacts/t2_sources/ecdsa_malleability_check.txt`。
因此，EUF-CMA 本身不能推出逐字节相同的 flight 一致性。应当把一致性定义在被签名的
transcript 上，要求规范编码／强不可伪造签名，或者先利用 Finished 对完整 transcript
的绑定，再作这一跳。

**证伪尝试**

采取的方法：

```
1. 不修改代码，按原样运行随包基准，共七个配对轮次。
2. 在实际服务器接收／签名／发送、客户端接收／验证以及 ShapedLink.flush 调用周围

3. 将端到端 H-C 差值与实测服务器计算、客户端计算、首个 flight 的计划序列化等待、
   实际等待以及剩余误差逐项比较。
4. 连续运行已编译的 Rust 原型十次，检验其字节数前提。
```
